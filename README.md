# 明石布 スマホコントローラー 本ロボver. 
#### byほぼclaude

ロボットを**スマホ(またはPCのブラウザ)から操作・監視**するためのシステムです。
さらに、**カメラで雑巾を見て、折れ・よれ・歪みがあるとスマホが振動して知らせてくれる**機能がついています。

> 動作確認の前提: Ubuntu(PC) + USBカメラ + マイコン(STM32など)をUSBで接続

## 1. できること

| 機能 | 内容 |
| :--- | :--- |
|  ロボット操作 | 画面のボタン(またはキーボード)で、マイコンに1文字のコマンドを送る |
|  Yaw角表示 | ロボットの向き(角度)をリアルタイム表示。タップで0°にリセット |
|  GCS昇降表示 | 昇降機構の高さを 0〜100% で表示 |
|  4輪電流バー | FL / FR / RL / RR の電流を棒グラフで表示(多いと赤くなる) |
|  コントローラー接続表示 | `CON: OK` / `CON: LOST` |
|  試合タイマー | 3分の試合時間と、追加タイミングの通知(音+振動) |
|  雑巾のジャム検知 | カメラ映像から雑巾の折れ・歪みを判定し、スマホに赤い警告+振動 |

## 2. 全体のしくみ

登場するプログラムは3つ+マイコンです。

```
 ┌──────────────┐  USBシリアル   ┌─────────────────────────         ┐
 │   マイコン     │ ◀───────────▶ │  ① robot_server.py       │
 │ (STM32など)   │  文字を送受信   │             全員の情報を中継   │
 └──────────────┘               └──────▲─────────────▲─────────┘
                                       │             │
                          POST(HTTP)   │             │ WebSocket(常時接続)
                                       │             │
                       ┌───────────────┴──┐   ┌──────┴──────────────┐
                       │ ② cloth_detector │   │ ③ robot_index.html   │
                       │   .py            │   │  スマホのブラウザ画面  │
                       │ 「目」: カメラで  │   │  「操作盤」           │
                       │  布をチェック     │   └─────────────────────┘
                       └──────────────────┘
```

- **robot_server.py**

  マイコンから届いた情報(角度・電流など)と、カメラ係から届いた「布の状態」を集めて、1秒に10回スマホへ配ります。逆に、スマホから届いたボタン操作をマイコンへ伝えます。
- **cloth_detector.py**

  カメラを見て「雑巾がきれいか」を判断し、結果を受付係に報告します。
- **robot_index.html**

  スマホのブラウザに表示される画面。受付係から届いた情報を表示し、ボタンが押されたらrobot_server.pyへ伝えます。

### データの流れ(2パターン)

**① ボタンを押したとき(スマホ → ロボット)**

1. スマホでボタンをタップ(例: `RESET YAW`)
2. ブラウザが `R` という1文字をWebSocketで送る
3. `robot_server.py` が受け取り、USBシリアルでマイコンに `R` を書き込む
4. マイコンが `R` を見て処理(Yaw角リセット)

**② 布が折れているとき(カメラ → スマホ)**

1. `cloth_detector.py` がカメラ画像を解析し「NG(折れ・凹み)」と判定
2. HTTP POST で `robot_server.py` に報告(`/api/cloth_alert`)
3. `robot_server.py` が全スマホに配信
4. スマホ画面が赤く点滅し、振動する

## 3. ファイル構成

```
pc_to_phone/
├── robot_server.py     # ① サーバー(ポート8000)
├── cloth_detector.py   # ② 検知(カメラ)
├── robot_index.html    # ③ スマホ用の画面
├── yolov8s-world.pt    # YOLO-Worldの学習済みモデル(あれば使う)
└── README.md           # このファイル
```

| ファイル | 使っている技術 | 役割 |
| :--- | :--- | :--- |
| `robot_server.py` | Python / FastAPI / uvicorn / pyserial | シリアル通信、WebSocket、布アラートの受信、画面の配信 |
| `cloth_detector.py` | Python / OpenCV / NumPy / (ultralytics) | 布の形状チェック |
| `robot_index.html` | HTML + CSS + JavaScript | ブラウザの操作画面(タイマー、振動、音もここ) |

## 4. 準備するもの

**ハード**
- PC(Ubuntu)
- マイコン(USBでPCに接続)
- USBカメラ(布検知を使う場合)
- スマホ(Android + Chrome 推奨)

**ソフト**
- Python 3.9以上
- 必要ライブラリ: `fastapi` `uvicorn` `pyserial` `opencv-python` `numpy`
- (任意)`ultralytics`(YOLO-Worldを使う場合。なくてもOpenCVだけで動く)

## 5. 初回セットアップ(1回だけ)

### 手順1: プロジェクトのフォルダへ移動

```bash
cd ~/pc_to_phone
```

### 手順2: 仮想環境を作る(推奨)

Ubuntu 24 では、直接 `pip install` するとエラーになることがあるので、仮想環境を使うのが安全です。

```bash
python3 -m venv venv
source venv/bin/activate
```

→ 行頭に `(venv)` が付けば成功。**以降、新しいターミナルを開くたびに `source venv/bin/activate` が必要**です。

### 手順3: ライブラリをインストール

```bash
pip install fastapi "uvicorn[standard]" pyserial opencv-python numpy
```

YOLO-Worldも使いたい場合(任意・容量が大きいです):

```bash
pip install ultralytics
```

### 手順4: USB機器を使う権限をもらう

```bash
sudo usermod -a -G dialout $USER
sudo usermod -a -G video $USER
```

→ **一度ログアウトして再ログイン**(または再起動)すると反映されます。

すぐ試したいだけなら、一時的にこれでもOK(再接続すると戻ります):

```bash
sudo chmod 666 /dev/ttyACM* /dev/ttyUSB* /dev/video* 2>/dev/null
```

### 手順5: 機器の番号を確認する

**マイコンのシリアルポート**

```bash
ls /dev/ttyACM* /dev/ttyUSB*
```

→ `/dev/ttyACM0` などが出ればOK(デフォルトは `/dev/ttyACM0`)。

**カメラの番号**

```bash
ls -l /dev/video*
```

→ `/dev/video0`, `/dev/video1`... の数字がカメラ番号。1台のカメラが複数の番号を持つことがあります。

詳しく見たい場合:

```bash
sudo apt install v4l-utils
v4l2-ctl --list-devices
```

## 6. 毎回の起動手順

**ターミナルを2つ**使います。(布検知を使わないなら①だけでOK)

### ステップ1: サーバーを起動(ターミナル1)

```bash
cd ~/pc_to_phone
source venv/bin/activate
python3 robot_server.py
```

ポート名が違うとき:

```bash
SERIAL_PORT=/dev/ttyUSB0 python3 robot_server.py
```

ボーレートを変えたいとき:

```bash
SERIAL_PORT=/dev/ttyUSB0 BAUD_RATE=115200 python3 robot_server.py
```

**成功の目印**

```
[Serial] Connecting to /dev/ttyACM0 (Baud: 115200)...
[Serial] Connected successfully!
```

> ⚠ マイコンがつながっていなくても、サーバー自体は起動します(1秒ごとに再接続を試みます)。

### ステップ2: PCのIPアドレスを調べる

```bash
hostname -I
```

→ `192.168.x.x` のような数字が出ます(最初のものを使う)。

### ステップ3: スマホをPCと同じネットワークにつなぐ

おすすめは次のどちらか:

- **スマホのテザリング**にPCをつなぐ(いちばん簡単)
- PCのホットスポットにスマホをつなぐ

### ステップ4: スマホのブラウザで開く

```
http://<ステップ2のIPアドレス>:8000
```

例: `http://192.168.43.100:8000`

- 画面右上が **`ONLINE`**(緑)になれば接続成功
- `[FULL]` ボタンで全画面表示
- **最初に画面を1回タップ**してください(ブラウザの仕様で、タップしないと音と振動が有効にならない)

### ステップ5: 布検知を起動(ターミナル2)

```bash
cd ~/pc_to_phone
source venv/bin/activate
python3 cloth_detector.py
```

**成功の目印**

```
[ClothDetector] カメラのオープンに成功しました！(解像度: 640x480)
[ClothDetector] Running cloth inspection loop.
```

カメラ映像のウィンドウが開きます。

| キー | 動作 |
| :---: | :--- |
| `d` | 歪み検知のON/OFF切り替え |
| `q` | 終了 |

### 終了のしかた

各ターミナルで `Ctrl + C`(布検知はウィンドウ上で `q` でも可)。

## 7. スマホ画面の見方と操作

### 画面の各部分

| 場所 | 表示内容 |
| :--- | :--- |
| 上部バー | 振動の強さ切替 / 歪み検知ON-OFF / 全画面 / 接続状態 |
| タイマー | 試合時間。`START` / `STOP` と `RESET` |
| 布アラート | 布の異常時だけ出る赤いカード(下で説明) |
| ROBOT POSE / YAW | ロボットの向き(度)とコンパス。**タップで0°リセット** |
| GCS 昇降 | 昇降の高さ(%)とゲージ |
| SYSTEM / 4-WHEEL CURRENT | `CON: OK/LOST`、FL・FR・RL・RRの電流バー |
| ACTION PAD | 操作ボタン |
| 直近送信コマンド | 最後に送ったコマンドと時刻 |

**接続状態バッジ**

| 表示 | 意味 |
| :--- | :--- |
| `ONLINE`(緑) | サーバーとつながっている |
| `RECONNECTING`(橙・点滅) | 再接続中(1秒ごとに自動で試す) |
| `OFFLINE`(赤) | 最初の接続前 |

**電流バーの色**: 緑 → 橙 → 赤の順に電流が大きい(表示値400で満タン)。

### ボタンとキーボードショートカット

| ボタン | キー | マイコンに送る文字 |
| :--- | :---: | :---: |
| LEFT_CATAPULT | `T` | `T` |
| RIGHT_CATAPULT | `E` | `E` |
| EMERGENCY STOP(非常停止) | `S` | `S` |
| RESET YAW | `R` | `R` |
| タイマー START/STOP | `Space` | (マイコンには送らない) |

> ⚠ **注意**: 画面のボタン名は `T`=LEFT_CATAPULT / `E`=RIGHT_CATAPULT ですが、「直近送信コマンド」欄の表示は `T`=RIGHT / `E`=LEFT と**左右が逆**になっています(`robot_index.html` の `labelMap`)。実際にマイコンへ送られる文字は同じなので動作は変わりませんが、混乱しないよう、どちらかに揃えてください。

### 試合タイマー

`START` を押すと進み、次の時間に通知(チャイム+振動)が出ます。

| 経過時間 | 表示 |
| :---: | :--- |
| 0:30 | 1回目の追加(10枚) |
| 1:00 | 2回目の追加(10枚) |
| 2:00 | +スーパー2枚 |
| 2:30 | バケツ解禁 |
| 3:00 | 試合終了 |

### 布アラート

布の異常が検知されると、タイマーの下に**赤いカードが点滅**して次が起きます。

- 判定の理由(例: `【折れ・凹み / 角のめくれ】`)と数値(Conv / Rect)を表示
- スマホが振動(正常に戻るか、検知OFFにするまで繰り返す)

正常なときは緑のカードで「正常 (まっすぐ)」と表示します。

### 振動の強さ

上部の `振動: 最大` ボタンを押すたびに **最大 → 標準 → 小** と切り替わります。

>  **iPhone(Safari)は振動に対応していません**(Appleの仕様)。振動を使うには **Android + Chrome** を使ってください。画面の点滅は iPhone でも動きます。

## 8. 布の検知のしくみ

### 全体の流れ(cloth_detector.py)

1. カメラから1フレーム取得(640×480)
2. 布を見つける
   - **YOLO-World があるとき**: 「towel / cloth / rag」を AI で探して枠を取る
   - **ないとき**: 画面全体から、いちばん大きい塊を布とみなす(OpenCVのみ)
3. 枠の中を白黒に変換し、**大津の二値化**(明るさで自動的に2色に分ける)で布の形(マスク)を作る
4. 形を**4つの指標**でチェック(下の表)
5. 直近5フレームのうち過半数がNGなら「NG」と確定(一瞬のノイズで鳴らないようにする)
6. 結果を `robot_server.py` へ送信

>  背景と布の明るさに差があるほど、きれいに検知できます。机の色が布と似ていると精度が落ちます。

### 4つの判定

| チェック | 計算 | NGになる条件(初期値) | 警告の名前 |
| :--- | :--- | :--- | :--- |
| 凸性 | 輪郭の面積 ÷ 凸包の面積 | 0.90 未満 | 折れ・凹み |
| 矩形度 | 輪郭の面積 ÷ 最小外接長方形の面積 | 0.80 未満 | 長方形の崩れ |
| コーナー数 | 輪郭を多角形に近似したときの頂点数 | 6個より多い | 角のめくれ |
| 縦横比 | 長辺 ÷ 短辺 | 本来の比(200:150 = 約1.33)から ±25% 超 | 縦横比の歪み |

**用語の説明**
- **凸包**: 輪郭にゴムひもをかけたときの形。布が折れて凹むと、輪郭がゴムひもより小さくなるので数値が下がる
- **矩形度**: 布がどれだけ長方形に近いか。1.0 に近いほど長方形

その他:
- 布の面積が小さすぎる(400px未満)/輪郭が見つからないときも異常扱い
- 枠が小さすぎる(35px未満)ものは無視

### サーバーへの送信ルール

- 状態が**変わった瞬間**に送る
- NGが続いている間は **0.5秒ごと**に送る
- 布が見えなくなって1秒たつと `NOT_DETECTED` を1回送る

## 9. マイコン側の作り方(通信ルール)

- ボーレート: **115200 bps**
- 1行 = 1メッセージ(**改行 `\n` で区切る**)
- マイコンは `printf` でカンマ区切りの文字列を送る

### ① ロボットの状態 `DATA`

```c
printf("DATA,%d,%d,%d,%d,%d,%d,%d\r\n",
       yaw_mrad, con_alive, gcs, steer_fl, steer_fr, steer_rl, steer_rr);
```

| 順番 | 項目 | 内容 |
| :---: | :--- | :--- |
| 1 | `yaw_mrad` | Yaw角をミリラジアンで(例: 1570 = 約90°) |
| 2 | `con_alive` | コントローラー接続中なら `1`、切断なら `0` |
| 3 | `gcs` | 昇降の高さ。0〜100 は%、**100より大きい値は÷10**して%にする(例: 755 → 75.5%) |
| 4〜7 | 電流 FL, FR, RL, RR | サーバーが**÷100**して画面に表示(例: `32000` → `320`) |

- 項目は**8個以上**ないと読み飛ばされます。
- 9個目に GCS の値を付けると、3番目ではなく9番目が優先されます。

### ② 昇降だけ送る `GCS`(任意)

```
GCS,<値>\n
```
`DATA` と同じルールで、値が100より大きければ÷10されます。

### ③ マイコンが受け取るコマンド(1文字)

| 文字 | 意味(スマホのボタン) |
| :---: | :--- |
| `R` | Yaw角を0°にリセット |
| `T` | LEFT_CATAPULT |
| `E` | RIGHT_CATAPULT |
| `S` | 非常停止 |

>  `S`(非常停止)は**必ずマイコン側のプログラムで安全に止まる処理**を入れてください。スマホ/Wi-Fi経由の停止は、通信が切れると届きません。本番の安全は、物理の非常停止スイッチを優先してください。

## 10. 設定を変えたいとき

### cloth_detector.py の先頭にある定数

| 変数 | 初期値 | 意味 |
| :--- | :---: | :--- |
| `CAMERA_ID` | `4` | カメラ番号(`/dev/video4`)。**環境変数ではなくコードを直接編集** |
| `W, H` | 640, 480 | カメラ解像度 |
| `REAL_cloth_l` / `REAL_cloth_s` | 0.200 / 0.150 | 布の実寸(m)。縦横比の基準になる |
| `persentage` | 0.10 | YOLOの信頼度のしきい値 |
| `BOMP_score` | 0.90 | 凸性のしきい値(上げるほど厳しい) |
| `SHAPE_score` | 0.80 | 矩形度のしきい値(上げるほど厳しい) |
| `corner` | 4 | 想定するコーナー数 |
| `ditect_frame` | 5 | 安定化に使うフレーム数 |
| `MIN_ALERT_INTERVAL` | 0.5 | NG中の送信間隔(秒) |
| `SERVER_HTTP_URL` | `http://localhost:8000/api/cloth_alert` | サーバーのアドレス |

>  NGが出すぎるなら `BOMP_score` や `SHAPE_score` を下げる、見逃すなら上げる。**1回に1つだけ**変えて試すと原因が分かりやすいです。

### robot_server.py

| 設定 | 方法 |
| :--- | :--- |
| シリアルポート | 環境変数 `SERIAL_PORT`(初期値 `/dev/ttyACM0`) |
| ボーレート | 環境変数 `BAUD_RATE`(初期値 `115200`) |
| 待受ポート | コード末尾の `port=8000` |
| GCSの上限 | `MAX_GCS_HEIGHT = 100.0` |

## 11. トラブルシューティング

| 症状 | 原因の候補 | 対処 |
| :--- | :--- | :--- |
| `bash: .../setup.bash: そのようなファイルやディレクトリはありません` | `~/.bashrc` に存在しない `source` 行がある(このプログラムとは無関係) | `nano ~/.bashrc` で該当行を消すか `#` でコメントアウト |
| `[Serial] Connection error ... Reconnecting` が繰り返される | ポート名が違う / 権限がない / マイコン未接続 | `ls /dev/ttyACM* /dev/ttyUSB*` で確認 → `SERIAL_PORT=... python3 robot_server.py` |
| `Permission denied` | USBの権限がない | 手順4を実施(再ログイン)。急ぎは `sudo chmod 666 /dev/ttyACM0` |
| スマホで画面が開かない | 別のネットワークにいる / IPが違う / ファイアウォール | PCとスマホが同じネットワークか確認。`hostname -I` を再確認。Ubuntuなら `sudo ufw allow 8000` |
| `RECONNECTING` のまま | サーバーが落ちている | ターミナル1のエラーを確認 |
| 角度や電流が変わらない | マイコンが `DATA,...` を送っていない | `DATA` の項目が8個以上か、ボーレートが115200か確認 |
| カメラが開かない | 番号違い / 他のアプリが使用中 | `ls -l /dev/video*` で確認 → `cloth_detector.py` の `CAMERA_ID` を変更。他のカメラアプリを閉じる。他の番号は自動検索もされる |
| `ultralytics is not installed` と出る | YOLOが未インストール | 異常ではない。OpenCVモードで動く。使いたいなら `pip install ultralytics` |
| YOLOモデルが読み込めない | `yolov8s-world.pt` がない/壊れている | ファイルを同じフォルダに置く。失敗しても自動でOpenCVモードに切り替わる |
| 布がよく誤検知される | 背景と布の明るさが近い / 照明が不安定 | 暗い単色の背景にする、照明を安定させる、しきい値を調整(第10章) |
| 布アラートがスマホに出ない | 歪み検知がOFF / サーバー未起動 | 画面上部が `歪み検知: ON` か確認。サーバーを先に起動する |
| スマホが振動しない | iPhoneはSafariが非対応 / 画面を未タップ | Android + Chrome を使う。画面を1回タップする |
| 音が鳴らない | 画面を未タップ / マナーモード | 画面を1回タップ。音量を確認 |
| SSH接続先でカメラ画面が出ずエラーになる | ディスプレイ(GUI)がない | 画面のあるPCで実行するか、`ssh -X` を使う(画面表示部分は例外処理されているので、エラーが出ても止まらない場合がある) |

## 12. 用語集

| 用語 | 意味 |
| :--- | :--- |
| **Yaw(ヨー)** | ロボットが上から見て、どちらを向いているかの角度 |
| **mrad** | ミリラジアン。1000mrad ≒ 57.3° |
| **GCS** | このロボットの昇降機構(画面では高さ%) |
| **シリアル通信** | USBケーブルで文字を1文字ずつやり取りする方法 |
| **WebSocket** | ブラウザとサーバーが「つなぎっぱなし」で会話できる仕組み。画面の更新に使う |
| **HTTP POST** | プログラムがサーバーへデータを1回送る方法。布検知の報告に使う |
| **FastAPI / uvicorn** | Pythonで簡単にWebサーバーを作るための道具 |
| **OpenCV** | 画像処理のライブラリ |
| **YOLO-World** | 「towel」などの言葉を指定して物体を探せるAI |
| **大津の二値化** | 画像の明るさを見て、自動で白と黒に分ける方法 |
| **凸包** | 形を囲む最小の凸な図形(ゴムひもをかけた形) |
| **ヘッドレス** | 画面(ディスプレイ)なしで動かすこと |
